# نتائج تدقيق المصادقة وواجهات API

## نطاق المراجعة

شملت المراجعة مسارات `/api/admin/login` و`/api/health` ومسارات OAuth القديمة، وسياق tRPC، وحمايات `protectedProcedure` و`adminProcedure`، ومساعدات الأخطاء، ومسارات `auth` و`admin`، إضافة إلى عميل لوحة الإدارة المستقلة.

## المشاكل المؤكدة

| الأولوية | الموقع | المشكلة | الأثر |
|---|---|---|---|
| حرجة | `server/routers/admin.ts` | `updateUserStatus` يتجاهل `isActive` ويكتب الدور فقط | لا تتغير حالة المستخدم فعلياً |
| عالية | `server/routers/admin.ts` | قائمة الاشتراكات تجلب النشطة فقط مهما كان مرشح الحالة | لا يمكن عرض الملغاة أو المنتهية |
| عالية | `server/routers/admin.ts` | تحديثات الاشتراك المباشرة بلا تحقق وجود أو معاملة | نجاح زائف وتعارض مع قواعد الاشتراك |
| عالية | `server/_core/context.ts` | JWT يتحقق من البريد دون مطابقة `adminId` | قبول هوية غير متسقة إذا أُعيد استخدام مطالبة مختلفة |
| عالية | `server/routers/auth.ts` | `auth.login` العام ينشئ/يحدّث مستخدمين من مدخلات يرسلها العميل | مسار هوية غير مناسب للإنتاج إذا استُخدم بديلاً عن OAuth |
| متوسطة | `server/_core/oauth.ts` | مسارات OAuth معلنة لكن `syncUser` موقوفة | سلوك 500/مضلل للمستهلكين القدامى |
| متوسطة | `server/routers/notifications.ts` | بعض فحوص المدير ترمي `Error` عادي وتستبعد `super_admin` | أكواد خطأ غير صحيحة وعدم اتساق الصلاحيات |
| متوسطة | `server/routers/admin.ts` | بيانات الرسم البياني عشوائية | لوحة الإدارة تعرض مؤشرات غير حقيقية |
| متوسطة | `tests/server/tests/security.test.ts` | الاختبارات تستهدف REST غير موجود | ضوضاء 404 لا تقيس عقد API الحالي |

## قرار الإصلاح في هذا القسم

سيتم أولاً إصلاح العيوب التي تؤثر مباشرة على صحة الصلاحيات والبيانات: مطابقة `adminId`، تصحيح تحديث حالة المستخدم، جعل ترشيح الاشتراكات حقيقياً، استخدام مساعدات تحقق موحدة، وحماية مسار تغيير حالة الاشتراك بالمعاملة الذرية. ستُفصل إعادة تصميم OAuth ومسار `auth.login` العام كقرار معماري مستقل إذا كان التطبيق سيستمر في دعم OAuth؛ لا يجوز تحويلهما تلقائياً أثناء هذا القسم.
